OpenGL Binding Implementation TODO
==================================

Scope
-----
- Primary implementation file: src/GL.hx.
- Native loader: include/glad/glad.h and src/glad.c.
- Current GLAD loader was generated for OpenGL 3.3 compatibility profile,
  with GL_ARB_vertex_attrib_binding as the only generated extension.
- The target baseline is OpenGL 3.3; this is not an OpenGL 4.5 baseline.
- Optional newer APIs and extensions must be detected and used only when loaded.
- GL_ARB_vertex_attrib_binding is optional and is used for separated vertex
  attribute state when available.
- The renderer currently has some Direct State Access usage, which must remain
  guarded by version/extension checks until an OpenGL 4.5 or ARB fallback is
  explicitly adopted.
- This TODO covers native GL bindings and renderer integration. GPU APIs from
  SDL and SDL rendering APIs are excluded.


Phase 1: Audit Existing GL.hx
-----------------------------
- [ ] Confirm that GL.hx uses OpenGL 3.3 as the supported baseline.
- [ ] Preserve compatibility-profile support unless a deliberate core-profile
      migration is documented.
- [ ] Document any newer APIs or extensions requested from GLAD explicitly.
- [ ] Do not require OpenGL 4.5 by default.
- [ ] Document which APIs are required by the renderer and which are optional.
- [ ] Add a GL loader initialization status check with a clear error if loading
      fails.
- [ ] Verify the actual loaded GL major/minor version before using APIs newer
      than the 3.3 baseline.
- [ ] Fall back to legacy-compatible VAO setup or report an unsupported configuration when
      GL_ARB_vertex_attrib_binding and OpenGL 4.3+ APIs are unavailable.
- [ ] Remove or clearly separate GL 1.x/2.x compatibility APIs from modern
      engine bindings.
- [ ] Add a version-and-extension report to Runtime startup logging.

Suggested Implementation Order
------------------------------
1. Set and verify the OpenGL 3.3 GLAD baseline and optional extensions.
2. Fix GL.hx native types and high-risk signatures.
3. Add context/query/debug state APIs.
4. Complete shader, program, uniform, VAO, buffer, and draw APIs.
5. Complete texture, framebuffer, and renderbuffer APIs.
6. Improve Renderer resource lifetime and state caching.
7. Add pixel, sync, query, transform-feedback, and compute support.
